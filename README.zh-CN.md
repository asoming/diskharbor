# 盘清 · DiskHarbor

[English](README.md) · [简体中文](README.zh-CN.md) · [GitHub](https://github.com/asoming/diskharbor)

**盘清** / DiskHarbor 是运行于 Linux、Windows 和 macOS 的本地磁盘空间分析工具。扫描指定位置，看懂文件占用，审阅符合条件的项目后再移入系统回收站。

**0.1.0-alpha.12 是未签名预发布版本，不是稳定版。** 测试只覆盖指定流程和夹具，不代表所有文件系统、云服务或操作系统环境均已兼容。

[下载 alpha.12](https://github.com/asoming/diskharbor/releases/tag/v0.1.0-alpha.12)：提供 Linux x64 DEB/tar.gz、Windows x64 EXE，以及 macOS ARM64/Intel 两种 DMG。请选择对应系统和架构，并使用 `SHA256SUMS.txt` 核对文件。本轮测量及保留的早前性能失败见下文；macOS 包尚未公证。

## 已有功能

- 按需扫描元数据，区分磁盘占用与文件内容大小；展示范围、时间、卷信息、跳过项和读取错误。
- 虚拟化文件树与文件列表，支持搜索、排序、大小/分类筛选、按需展开和分页；有界排序缓存减少重复工作，刷新排序/筛选结果时保持文件树视口位置。
- 支持方向键、Home/End、Page Up/Down、空格和 Enter，保持焦点可见；支持中英文及 100%/200% 缩放。
- 会话内记忆浏览路径、展开、已载入页数和滚动；同根重扫后按路径映射新 ID 恢复。
- 隐藏项与系统/应用数据的显示筛选不改变统计或清理保护；同根保留设置，换根或重启重置。
- 查看元数据、复制路径、在文件管理器显示，查看可能关联的应用及云端状态依据。路径匹配不能证明文件归属或应用已安装。
- 在三平台经核验的本地存储上，显式预览受支持的文本和图片。
- 识别部分标准 Chrome、Chromium、Firefox 缓存布局，提供手动“仅缓存”清理指引。
- 审阅文件或符合条件的整个文件夹，经原生对话框确认后移入系统回收站；可停止尚未开始的操作。
- 保存最多 50 条本地操作记录，逐项写入检查点，异常退出后保守恢复状态。
- 手动核验从扫描起点至当前的可用空间，或查看独立的操作前后测量。
- 打开系统回收站并查看恢复指引；没有自动还原、永久删除或清空回收站操作。

无需账号。扫描路径和内容在本地处理，应用不上传这些信息，不发送遥测。

## 扫描、显示与预览边界

只扫描所选根，不跟随符号链接；发现其他卷或挂载边界时需单独扫描。Linux 使用包含绑定挂载的挂载表信息，Windows/macOS 使用原生卷元数据。未知保持未知。扫描完成不是事务快照，也不证明已覆盖整盘。

停止扫描需等待当前操作系统读取返回，保留已发现结果，期间不能提前开始另一扫描。最多展示 100 条读取错误详情；重试失败范围会替换扫描，不合并统计、不提权、不修改权限。

显示规则结合点号路径、已知系统/应用位置以及可取得的原生隐藏/系统属性。隐藏内容仍计入大小和父目录比例；隐藏数量是当前查询范围的数量，不是全卷数量。显示受保护项目不会授予清理权限。

浏览记忆最多保留 16 个视图，每视图 16 个展开文件夹；自动恢复每文件夹最多 500 行、合计 2,000 行。原位置被隐藏或不可用时回到可用上级；不会自动恢复勾选或打开文件详情。

预览必须显式触发并绑定当前扫描 ID；有界读取前后会复核文件、父目录和已打开对象的身份。内容不会持久化到应用缓存或操作历史。

- UTF-8 文本：最多读取前 **64 KiB**，超出时提示截断。HTML 片段按字面显示；拒绝二进制和不支持的编码。
- PNG/JPEG/WebP：最多 **8 MiB**、单边 **8,192 像素**、总计 **16,000,000 像素**；拒绝 SVG、PDF、动画和不支持的格式。
- Linux 要求文件位于允许列表内、经核验由 `/dev/` 支持的本地文件系统；拒绝网络、FUSE、overlay、虚拟及未知文件系统。
- Windows/macOS 使用编译后的原生策略与元数据/读取辅助程序。策略缺失、元数据不可核验、非本地存储、占位文件、重解析点/符号链接或身份变化时拒绝操作，不降级为宽松的 Node 正文读取。

原生占位文件保护采取保守策略，但不代表所有真实云服务均已实测，也不能消除全部提供方竞态。“本地可用”不证明文件从未同步。

## 清理、历史与恢复

清理拒绝受保护的隐藏/配置/系统/应用数据路径、链接、共享硬链接、不支持的名称及不完整结果。所选目录的每个后代都必须通过检查；一个后代受阻便阻止整个目录操作。文件系统根、个人文件夹根和当前扫描根受保护。

- 父子归并前最多 **500 个选择**。选择父目录会替代其已选后代；父目录受阻时不会退回操作子项。
- 同一计划的目录清单共用 **10,001 个节点上限**，包含所选目录根；单一目录最多 10,000 个后代。
- 计划仅可使用一次，须在 **两分钟**内接受。原生确认框是最后确认；每项操作前重新核对身份及目录内容。
- 只调用系统回收接口，失败不会改用永久删除。停止剩余任务不会撤销已完成或正在进行的操作。
- 开始前必须成功持久化日志，后续写入失败会停止余项。历史损坏需显式重置，不会静默覆盖。
- 重启后，待处理项变为已取消，最后处于处理中项变为结果不确定；不自动续作，也不凭原路径消失认定成功。

系统回收 API 按路径操作，复核无法消除所有文件系统竞态。历史是操作记录，不是备份。

恢复时先核对原名称、路径和删除时间，再使用系统的还原/放回操作。同名冲突先取消并比较两份，再选择系统提供的保留两份或其他位置选项；不保证自动重建缺失的原目录。核对恢复后的**名称、位置与内容**，然后主动重扫；历史不监测外部还原。结果不确定时同时查看原位置和回收站。永久删除或清空回收站后，盘清无法恢复。

**Linux 还原限制：** 隔离的 GIO CLI 测试有六项严格 ASCII/目录/冲突检查通过，但 GIO 2.72.4/GVFS 1.48.2 与 GIO 2.80.0/GVFS 1.54.4 的中文名称诊断均保留字节、却恢复为字面 `\xhh` 转义名称。此案例**不计为通过**，报告为 `passed-with-limitations`。参见 [GLib 还原实现](https://github.com/GNOME/glib/blob/2.72.4/gio/gio-tool-trash.c#L103)。文件管理器 GUI 还原及 Windows/macOS 还原仍未实测。

## 空间测量与浏览器缓存

空间测量针对**整个所在卷**，保留两端时间、总容量与可用空间；只有样本及根身份可比较时才显示带正负号的变化。未知不当成零。同卷回收通常不会立即释放空间，其他应用写入、快照与异步操作也会影响结果；它不是盘清保证释放的字节数。

手动核验比较扫描起点与显式复测，操作记录使用独立的操作前后时段。手动结果仅在当前扫描会话保留，不刷新列表、不写历史，替换扫描后清空。旧差值明确标注未核验，中断测量不会编造末端样本。

缓存匹配只读取当前扫描索引元数据，最多显示 50 个位置，要求标准路径与预期结构。未匹配不等于没有缓存，记录占用不等于可释放量；可能漏掉自定义或沙箱安装布局，也不推断本机浏览器版本。

指引只复制固定设置地址，让用户仅选择缓存文件/页面/图片，保留 Cookie、历史、密码和站点数据；不自动清理，也不放松受保护路径规则。盘清不观察浏览器操作结果，之后需主动重扫。Firefox 规则已记录 156.0.1 版本的真实浏览器验证；Chrome/Chromium 仍仅通过元数据夹具。当前安装的浏览器版本保持未知。

## 构建与运行

使用 **Node.js 24** 和 npm。Windows 还需 Python 3、Visual Studio 2022 Build Tools 的 **Desktop development with C++** 工作负载及 Windows SDK；macOS 需 Python 3 和 Xcode Command Line Tools。`prebuild` 与 `pretest` 会为当前 Electron 编译原生辅助程序；编译失败应修复环境，不能绕过保护。

```bash
npm ci
npm run build
npm start
```

开发前先运行 `npm run build:native`，再运行 `npm run dev`。`npm run preview` 仅预览浏览器界面，不能扫描或操作文件。

`test:performance` 创建 100,000 个真实同级文件、嵌套夹具及 1,000,000 条完整合成索引；`test:index` 独立测量生产索引，不包含 Electron，不能把其内存结果当成整应用内存。测试只使用生成夹具，但会消耗较多文件元数据、内存和时间。

仅 Linux 的 `npm run test:restore` 还需 `dbus`、`libglib2.0-bin`、`gvfs`、`gvfs-daemons`；使用私有 D-Bus/XDG 状态，仅处理自身已核验的回收 URI，并保留上文 CLI 中文名称限制。

```bash

npm run dist:linux  # Linux：deb 与 tar.gz
npm run dist:win    # Windows：NSIS 安装程序
npm run dist:mac    # macOS：DMG
```

请在目标操作系统上构建，产物位于 `release/0.1.0-alpha.12/`。这些是未签名 alpha 产物；macOS 的 ad-hoc 签名不等于开发者身份、公证或 Gatekeeper 分发批准。

## 验证依据

**核心回归：** [四平台运行 36293114784](https://github.com/asoming/diskharbor/actions/runs/36293114784)，源码 `abe3ee40ad46472dd95031ecf07eb3b82eaa4857`。每个平台运行 263 项单元测试：Linux 260 通过/3 平台跳过，Windows 224/39，两种 Mac 各 231/32，均无失败。24 份常规桌面报告全部通过、无渲染错误，包含每端 12 项导航检查。Linux 恢复单列为上文说明的 `passed-with-limitations`。

**性能：** [正式四平台运行 36292683561](https://github.com/asoming/diskharbor/actions/runs/36292683561)，源码提交 `12edec9d834af9951efe18856c1ba377c2dd37c7`，达到未放宽的预算：排序完成 p95 ≤200ms、取消反馈 ≤1 秒/观察到本地终态 ≤3 秒、百万记录整应用峰值 ≤1.5 GiB。其应用运行时代码与上方较晚的验证提交一致，两者之间只调整验证基础设施，未改变应用运行时。

| 平台 | 排序 p95 / 最大值 | 取消反馈 | 百万记录整应用峰值 | 结果 |
| --- | ---: | ---: | ---: | --- |
| Linux x64 | 66.7 / 98.7ms | 27.9ms | 1.2699 GiB | 通过 |
| Windows x64 | 63.2 / 93.0ms | 25.6ms | 1.0650 GiB | 通过 |
| macOS Intel | 166.2 / 199.3ms | 53.7ms | 1.1769 GiB | 通过 |
| macOS ARM64 | 101.7 / 236.3ms | 578.1ms | 1.3407 GiB | 通过 |

四端均完成 100,129 个真实文件扫描，包含 100,000 个同级空文件、深度 82，再保留 1,000,000 条完整合成记录；每端七项功能检查通过。保留全部 240 个固定排序样本，每次恰好一次生产查询，以界面/帧稳定完成和 nearest-rank 计算 p95。四端两次实际视口设置及中英文 200% 键盘操作均通过，焦点保持可见。

p95 通过不代表每次交互都低于 200ms：ARM 保留一次 **236.3ms** 排序和 **578.1ms** 取消反馈。早前失败仍作为证据保留：[alpha.11 运行 36252607354](https://github.com/asoming/diskharbor/actions/runs/36252607354) 的 Intel 排序 p95 为 265.9ms、ARM 取消反馈为 **2,309ms**；早前 ARM 数秒长帧的根因仍未证实。[运行 36291720088](https://github.com/asoming/diskharbor/actions/runs/36291720088) 保留视口布局修复前 Intel p95 231.5ms 的失败。[运行 36292439794](https://github.com/asoming/diskharbor/actions/runs/36292439794) 因 Electron 下载失败而未启动 Intel 应用，没有该端性能数据。不会删除这些记录或改标为通过。

这些是已记录 CI 硬件上的暖缓存元数据测试，不是统一 4 核/8 GiB 参考机或冷盘吞吐承诺。扫描/内存阶段每 100ms 汇总各进程工作集，会保守地重复计算共享页；计时交互阶段暂停同步采样。保留所有原始样本，正式运行关闭诊断与追踪模式。人工屏幕阅读器听测仍未完成。

本轮本机 Linux/X11 测量的排序 p95 为 **67.6ms**、百万条目整应用峰值为 **1.4347 GiB**，距内存预算约余 67 MiB。200ms 目标针对真实十万文件的界面负载，不是所有百万条目查询；百万阶段核验完整保留与整应用内存。

**安装升级与浏览器验证：** [四平台运行 36293120322](https://github.com/asoming/diskharbor/actions/runs/36293120322)，源码提交 `abe3ee40ad46472dd95031ecf07eb3b82eaa4857`。四个任务均通过五项包检查和四项浏览器检查。升级基线是已发布的真实 alpha.11 源码（`41eab5d9a2c2ddadd5ff71739df63a3197139024`）。在一次性环境中实际安装，从该基线升级，保留渲染沙箱，验证了盘清图标、夹具偏好/历史保留，再卸载。Linux 使用 DEB，Windows 使用当前用户 NSIS 安装程序，Mac 从只读 DMG 复制及替换应用包；Mac 这项检查不代表 Gatekeeper 分发批准或 pkg 安装器验收。

实际验证主机为 Ubuntu 24.04.5 x64、Windows Server 2025（10.0.26100）x64、macOS 26.6.2 ARM64 与 macOS 15.7.9 Intel。不能据此声称 Windows 10/11 桌面或更早 macOS 已兼容。

四端 Firefox **156.0.1** 使用真实标准配置/缓存布局中的隔离配置。缓存跨重启保留，原生仅缓存清理后产生新请求，Cookie、localStorage、书签和配置文件哨兵均保留。清理通过回环特权 WebDriver 调用 `nsIClearDataService.CLEAR_NETWORK_CACHE`，不是设置 GUI；盘清本身只提供手动指引，不调用该服务清理。

此前 Linux Chrome **152.0.7977.82** 实验使用自定义配置/缓存目录，原生仅缓存清理后 Cookie/localStorage/IndexedDB 哨兵保留；它不验证默认 Chrome 路径、Chromium、书签或密码。

## 仍存限制

- 真实云提供方水合、macOS TCC 对话框、可移动盘实际断开及人工辅助技术使用仍待现场验证；模拟故障不等于真实拔盘。
- 占用统计不包含目录自身元数据、保留空间和快照账目；未知占用可能使已知字节汇总不完整，未对 APFS 共享区段去重。稀疏/压缩元数据测试不代表所有文件系统已认证。
- 尚无自动缓存清理、重复文件检测、扫描快照、文档渲染、深色模式或自动恢复。
- 尚无签名/公证稳定发行版；一次性运行环境中的包测试不能覆盖每种安装程序、操作系统版本和企业策略组合。
