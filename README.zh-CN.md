# 盘清

[English](README.md) · [简体中文](README.zh-CN.md) · [GitHub](https://github.com/asoming/diskharbor)

盘清是一款本地运行的桌面磁盘空间分析工具。查看空间被什么占用，检查文件与文件夹，并在移入系统回收站前核对所选项目。

**中文名：** 盘清 · **英文名：** DiskHarbor

## 项目状态

**0.1.0-alpha.9 — 早期桌面 alpha。** 本轮补充系统回收站恢复指引，说明同名冲突、原目录缺失和恢复后检查。新增隔离 Linux 原生回收→GIO 命令行还原测试：本机和 CI 六项严格检查通过，但独立中文文件名诊断**未通过**，恢复报告为 `passed-with-limitations`。alpha.9 三平台 CI 作业与本机 Linux 包验证已完成，恢复限制仍明确保留。应用不会自动恢复文件或清空回收站；浏览器缓存仍仅提供指引，Windows/macOS 内容预览仍未开放。继续启用渲染进程沙箱。干净环境安装、Windows/macOS 签名安装包与完整平台适配仍待完成。

首个稳定版计划在 Linux、Windows 和 macOS 提供相同核心流程。当前 alpha 检查仅覆盖已测流程，不代表完整平台支持。

## 已实现功能

- **扫描范围详情：** 展开查看所选根路径、本地开始时间、耗时、扫描开始时的卷容量快照、可获得的设备/挂载信息及跳过类别。未知值明确标注；详情默认折叠，扫描更换后重置。
- **空间概览：** 展示真实扫描结果与文件分类，分别显示磁盘占用和文件逻辑大小。
- **文件浏览：** 可展开的文件树，支持懒加载、分页、虚拟行、键盘导航、排序、搜索，以及大小和分类筛选。
- **会话内浏览记忆：** 返回浏览范围时保留筛选、排序、展开目录和滚动位置。同一根目录重新扫描完成后，按精确路径找回浏览位置，使用新扫描中的条目 ID。
- **扫描取消：** 请求停止后保留已发现结果。当前文件系统调用必须返回，才会报告扫描已取消；等待提示在切换页面后仍可见，旧扫描仍活跃时不能开始新扫描。
- **读取问题与重扫：** 查看最多 100 项读取失败的路径及解释。用户明确选择后，可重扫失败目录；文件读取失败则重扫其所在目录。新扫描替换当前范围及汇总，不合并结果，并提供返回原范围重新扫描的入口。
- **文件详情：** 查看元数据与路径，在系统文件管理器中定位项目，复制路径。
- **按需内容预览：** 在经核验的 Linux 本地文件系统上，手动预览受支持的 UTF-8 文本及 PNG、JPEG、WebP 图片。查看项目详情不会自动读取内容。
- **浏览器缓存指引：** 从已扫描元数据识别 Chrome、Chromium、Firefox 的部分标准缓存布局，查看占用记录与匹配依据，复制固定的浏览器设置地址，并按步骤手动执行仅缓存清理。
- **确认后清理文件与目录：** 手动选择普通文件或符合条件的目录，审阅清单，通过系统原生对话框确认。目录的完整扫描内容必须通过元数据检查，并与当前文件系统一致，才会作为一个项目移入系统回收站。被阻止的目录不会只清理部分内容；回收失败不会转为永久删除。
- **清理进度与取消：** 查看逐项操作结果，停止尚未开始的操作。已经开始的系统回收调用可能继续完成；取消不会撤销已完成的移动。
- **系统回收站入口与指引：** 打开系统回收站，展开五步双语恢复说明，涵盖确认项目、系统操作、同名冲突、缺失目录及恢复后检查；最小窗口内支持键盘滚动。盘清不会自动恢复文件或清空回收站；能否恢复取决于项目是否仍在回收站以及系统能力。
- **持久化本地历史：** 在原生操作前及逐项结果产生后保存检查点，最多保留 50 条操作记录。中断任务不会自动继续；尚未开始的项目标记为已取消，最后记录为处理中但未记录结果的项目标记为结果不确定。不会因为原路径已经不存在就推定回收成功。
- **操作空间测量：** 新的清理记录显示操作前后时间、卷容量和可用空间，仅在可比较时显示带符号的变化。结果卡片与操作历史共用可展开的测量详情；旧记录明确标注未经核验。
- **空间核验：** 手动比较所在卷在扫描开始与本次核验时的可用空间，显示两个时间、容量与带符号的变化；无法比较时显示未知。同次扫描的结果跨页面和语言保留，不更新文件列表或写入操作记录。
- **本地双语使用：** 提供中英文界面，无需账号，不上传扫描得到的文件名、路径或文件内容。
- **Linux 应用入口：** 桌面条目支持中文名称**盘清**及英文名称 **DiskHarbor**。

## 扫描与重试边界

- 只扫描所选根，不跟随符号链接；发现其他卷或挂载边界时跳过，须单独扫描。Linux 挂载信息包含绑定挂载；仅按设备编号检测时，同设备边界可能无法识别。Windows/macOS 挂载位置及文件系统名称目前仍未知。普通隐藏文件仍在扫描范围内，清理保护另行判断。
- 卷总容量和可用空间为扫描开始时所在卷的快照，不是所选文件夹容量或实时可用空间。设备编号仅用于本次扫描，不是永久磁盘序列号。跳过计数针对已发现的入口，不代表其全部后代或字节；未知占用计数只涵盖已索引的文件/链接，不涵盖未读后代。未知占用不当作 0。
- 扫描完成前重新核对根路径的类型、设备和文件身份；检测到消失或替换时保留部分结果并报告失败。扫描不是事务快照，文件或设备可能在过程中变化；扫描结束不保证全盘覆盖。
- 取消会停止安排新的扫描任务，无法强行中断所有操作系统读取。阻塞调用返回前，界面会继续显示等待状态；此时仍可浏览已发现的结果，取消完成后标明不完整。
- 即使失败总数更多，错误详情最多保留 **100 项**。重试须由用户在当前扫描结束后明确发起，不会自动提权或修改文件权限。
- 重试为一个独立扫描，范围限于上次扫描根目录内符合条件的失败目录，或失败文件的父目录。原范围汇总会被替换，不会与新结果合并；不支持的文件名不能转为重扫路径。
- 文件树与文件列表的浏览记忆只保留在当前应用会话中，包括搜索、最小逻辑大小、排序、显示列、浏览范围、展开目录、已加载页数和滚动位置。同根重扫须等新扫描完成后恢复；旧位置未出现在新结果中时，回退到记忆中在本次扫描可用的最近祖先目录，不据此断言原目录已删除。更换扫描根目录或重启会清空记忆。键盘活动行只在精确路径已加载时恢复，不自动恢复清理勾选或打开文件详情。
- 最多记住 **16 个视图**，每视图 **16 个展开目录**。自动恢复最多加载**每目录 500 行、合计 2,000 行**；达到上限时会提示，可继续手动加载。新扫描完成前会保持待恢复状态，取消扫描也不会提前宣称恢复完成。

## 空间核验边界

- 扫描结束或取消后，明确点击**核验可用空间**；扫描期间会记录起始值，后续核验需要主动触发。核验绑定当前扫描及所选根路径，不接受另一个自报路径。它读取卷元数据，不读取文件正文或删除文件。
- 起始记录与每次新测量都在读取卷元数据前后核对根目录身份及解析后的实际路径；根发生变化或不可用时拒绝核验。缺少起始记录、卷特征或总容量变化时，差值为未知，并提供明确的重新扫描操作。这些复核不是原子文件系统快照，无法消除所有路径竞态。
- 差值为**本次可用空间减去扫描开始时的可用空间**，保留正、负和零。它描述整个所在卷，不是所选文件夹的大小或盘清保证释放的空间。同卷回收通常不会立即释放空间；其他应用写入、快照和系统异步处理也可能影响观测。
- 结果只在当前应用会话、同一次扫描内保留。重新核验先清除旧结果，失败不保留旧成功；换扫描清空并丢弃迟到回复，切页与切换语言保留同一结果。核验不刷新文件列表、不写操作记录、不清缓存或自动扫描；需要时明确点击**重新扫描**。
- 扫描或清理进行时不能核验。响应超时不代表底层文件系统读取已取消；当前读取实际结束或用户主动更换扫描前，后续核验与清理仍受阻。更换扫描会丢弃旧扫描上下文，但不保证旧系统调用已经停止。软件不观察或确认浏览器原生清理的完成结果。
- 新清理记录采用独立的**操作前后**时间段，每次读取卷数据前后使用同样的根身份和真实路径复核。结果与操作历史显示两端时间、可用空间和总容量，仅在可比较时记录数值差；缺少读数、根无法核对或卷特征变化时仍为无法比较。这是观测变化，不保证释放量，也不同于手动核验的扫描起点比较。
- 测量详情区分操作尚未开始、等待末端读数与测量中断。重启恢复未完成记录时，保留已有的有效起始读数，清除末端读数与差值。旧记录保留原有差值，并标注**“旧记录，未经卷身份核验”**，不会被升级为已核验测量。

## 浏览器缓存边界

- 规则覆盖 Linux、Windows、macOS 的部分标准布局，以可信用户或缓存位置为根。Chromium 系匹配要求受支持配置下的 `Cache/Cache_Data` 结构；Firefox 匹配要求 `cache2` 中包含 `entries` 与 `index`。仅有一个名为“Cache”的目录不会匹配。自定义位置、沙箱安装及未支持的布局可能不显示；没有匹配结果不代表没有缓存。
- 识别只查询当前扫描索引，不读取缓存内容，也不在扫描范围之外搜索。报告绑定扫描 ID，最多展示 **50 个位置**，明确区分部分结果；实际占用、逻辑大小和文件数分别显示，未知占用仍为未知。记录的占用不代表承诺可释放的空间。
- 扫描期间可手动刷新识别，扫描结束后自动更新报告；重新扫描会替换旧卡片。文件树入口只定位当前扫描中的匹配条目。
- 指引仅复制固定设置地址：Chrome/Chromium 为 `chrome://settings/clearBrowserData`，Firefox 为 `about:preferences#privacy`。不会启动浏览器、执行清理或写入清理历史。由用户在浏览器内只选择缓存文件、页面或图片，取消勾选 Cookie、历史记录、密码和站点数据，完成后重新扫描。重建缓存可能让部分页面首次访问变慢。
- 识别不会改变隐藏路径和应用数据的保护，不自动勾选，也不授权直接删除缓存。可展开查看规则、版本、来源与测试状态。本机浏览器版本未知；当前规则仍为 `validation: metadata-fixtures`，`validatedAppVersions` 为空。下述独立 Chrome 实验不等于标准安装路径或全部浏览器均已验证。

## 内容预览边界

- 当前仅在 Linux 开放内容预览，且必须确认文件路径与已打开句柄位于由 `/dev/` 设备提供的 ext2/ext3/ext4、XFS、Btrfs、F2FS、VFAT、exFAT 或 ntfs3 文件系统。拒绝网络、FUSE、overlay、虚拟及未知文件系统。Windows/macOS 预览明确返回平台未开放结果，扫描与清理流程仍可使用。
- 受支持的文本按 UTF-8 解码，最多读取开头 **64 KiB**，较长文本会标明截断。拒绝二进制内容及不支持的编码。受支持文本中的 HTML 片段按字面展示，不会执行。
- PNG、JPEG、WebP 图片必须不超过 **8 MiB**，**任一边不超过 8,192 像素**，且**总像素不超过 16,000,000**。显示前检查文件头与尺寸。拒绝 SVG、PDF、动画图片及其他不支持的格式。
- 每个请求绑定本次扫描 ID，使用同一文件句柄读取，并在读取前后复核文件与父目录身份。拒绝发生变化的文件、符号链接、硬链接、受保护路径及不支持的文件名。每次明确预览均重新读取，内容不写入应用缓存或操作日志。
- 尚未全面识别云占位状态。预览限制不能保证绝不触发云端文件下载，也不代表下载量上限；访问按需文件可能让其提供方下载内容。关闭预览会隐藏结果，不代表已经取消正在进行的系统读取。

## 清理边界

- 拒绝点号开头的路径、隐藏配置位置、受保护的系统或应用数据路径、符号链接、硬链接文件、不支持的文件名，以及扫描不完整或不可读取的项目。目录内任一后代项目不安全或发生变化，都会阻止整个所选目录的操作。文件系统根目录、用户主目录根和本次扫描根目录不能作为目录移入回收站。
- 每个计划在选择归并前最多接受 **500 个选择项**。同时选择父目录与子项时，只保留一次父目录操作；父目录被阻止后，不会转而处理子项。
- 一个计划内通过验证的目录清单合计最多 **10,001 个条目**，包含所选目录自身及所有后代项目。因此，只选一个目录时，最多允许 **10,000 个后代项目**；选择多个目录时共享同一上限。
- 计划只能执行一次，必须在两分钟内确认；按时确认的批次可以继续执行到该期限之后。原生操作前再次核验身份与目录内容。
- 清理开始前必须成功写入日志；后续日志写入失败会停止剩余操作。损坏的历史不会被悄悄覆盖，需要明确清空本地历史进行重置。清空历史不会删除或恢复用户文件。

需要恢复时，展开**查看恢复指引**，通过系统回收站处理：

1. 先核对名称、原路径和删除时间。结果不确定时，同时检查原位置和回收站。
2. 使用系统提供的**还原**或**放回原处**（Restore / Put Back）操作。
3. 遇到同名冲突，先取消并比较两份内容；优先采用系统提供的保留两份或其他位置，不要未经核对直接覆盖。
4. 原目录缺失时，按系统可用选项选择确认过的位置，不保证自动重建原目录。
5. 在文件管理器核对恢复后的名称、位置和内容，再回到盘清主动重新扫描。

操作记录保留当时的回收结果，不会监测外部还原。记录不是备份；永久删除或清空回收站后的内容不能通过盘清恢复。

## 从源码运行

推荐使用 **Node.js 24，最低要求为 22.12**，并安装 npm。在仓库目录运行：

```bash
npm ci
npm run dev
```

构建生产界面并通过 Electron 运行：

```bash
npm run build
npm start
```

`npm run preview` 仅提供浏览器界面预览，不能扫描磁盘或执行文件操作；这些流程需要在 Electron 应用中使用。

## 测试与打包

```bash
npm test
npm run build
npm run test:desktop
npm run test:navigation
npm run test:cache

# 仅 Linux

```

Linux 桌面集成测试需要带 `DISPLAY` 的图形会话，或使用 Xvfb：

```bash

```

运行桌面测试前先构建生产界面。`test:desktop`、`test:navigation`、`test:cache`、`test:scope` 和 `test:space` 在 Linux 均需要图形会话或 Xvfb，使用隔离的合成数据和独立应用配置。`test:desktop` 检查真实系统回收、操作测量及两次应用进程间的历史恢复，不扫描个人文件夹；`test:cache` 检查识别、指引、剪贴板结果及原有清理保护，不执行缓存清理。`test:scope` 检查双语范围详情、已记录的覆盖情况、扫描更换及合成读取错误的解释。`test:space` 使用隔离夹具，通过真实桌面界面检查手动核验、带符号和未知结果、会话保留及旧结果拒绝。

`test:restore` 仅支持 Linux，同样需要先生产构建、图形会话或 Xvfb，以及 `dbus`、`libglib2.0-bin`、`gvfs`、`gvfs-daemons` 软件包。它创建私有 D-Bus/GVFS 会话与独立 XDG 目录，不修改 `HOME`，不使用当前桌面的 GVFS 会话；每次还原仅针对已核实归属自身合成夹具的 URI。它验证系统 GIO 命令行，不是在盘清中新增还原 API。

**alpha.9 本机结果：** 202 项单元通过，0 跳过、0 失败；生产构建和 22 项原生检查通过。本轮尚未在本机重跑导航、缓存、范围及手动空间核验四套检查。

## 当前限制

- 浏览器缓存目前仅提供标准布局识别与手动指引；尚未实现应用缓存直接或自动清理、重复文件检测和扫描快照。
- 内容预览仅支持上述 Linux 文件系统和格式；尚未开放 Windows/macOS 内容预览，也未提供文档渲染、深色模式和应用内自动恢复。系统错误文本可能保留操作系统的语言。
- 实际占用不包含目录自身元数据。Windows 实际占用元数据与特殊卷处理仍有缺口；无法获得占用元数据的项目显示未知，概览仅汇总已知占用，因此可能低估总量。尚未识别 APFS 共享块及云占位文件状态。系统回收接口按路径操作，复核无法消除所有文件系统竞态。日志保存检查点，但如果崩溃发生在原生操作与结果记录之间，结果仍不确定，需要手动检查。
- Linux 还原证据仅覆盖隔离的 GIO 命令行。本机及 CI 中文名称案例字节保留但名称被错误转义，不计为通过；文件管理器 GUI、Windows/macOS 还原、不可用卷和完整恢复流程仍未验收。
- 此 Electron alpha **尚未达到 35 MB 的包体目标**。实际大小以生成的构建产物为准，不承诺更小的安装包。
- alpha.9 已通过 Windows/macOS 原生扫描/清理基础检查、导航、合成缓存布局、范围界面及空间核验检查；内容预览仍未开放，拒绝行为已验证。签名安装包与完整适配仍待完成。其系统回收站入口仍仅有模拟测试，完整手动还原流程尚未实测。
